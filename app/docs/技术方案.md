# 技术方案

定价参谋工作台的技术方案，分七部分：架构分层、数据表、参数文件、计算模块、页面路由、测试、启动方式。文中的「PRD」「MRD」「验收条例」指项目自己的规格文档，规则编号 R-xx、口径编号 C-xx、步骤编号 PT-xx 出自这些文档。

## 1 架构分层

单进程、单店、单用户，分层与产品框架一一对应。

| PRD 6.1 的层 | 代码 | 做什么 |
|-|-|-|
| 用户层 | 浏览器，只绑本机 127.0.0.1 | 店主一人使用 |
| 应用层 | advisor/main.py 页面路由，advisor/service.py 编排，advisor/tools.py 备份恢复 | 导入、健康度列表、单品建议（输入面板、采纳、忽略）、体检报告、设置、导出；整批事务；每次输入变化重算一版，只有输入变了的 SKU 旧建议过期 |
| 模型层 | advisor/calc.py 计算一，advisor/model.py 计算二，advisor/params.py 参数 | 计算一：保本价、毛利率、日均、库存天数、生命周期、数据不足、疑似偏高 / 偏低、改价事件、活动日、事件弹性与类目校准；计算二：候选价、生命周期目标、库存约束、竞品裁剪、建议区间、健康度、置信度、预估、解释四句 |
| 数据层 | SQLite 单文件 data/advisor.db | 只存一家店的数据，不跨店汇总 |
| 外部 | 店主导出的 CSV | 唯一数据来源；运行时不发任何外部请求 |

技术栈：Python 3.12、FastAPI、Jinja2 服务端模板、原生表单加少量本地脚本、SQLite、pytest、uv。单品页滑块（PT-09）若需要再引入 HTMX，文件放本地，不走 CDN。

## 2 数据表

| 表 | 主键 | 主要列 | 说明 |
|-|-|-|-|
| product | sku | name、category、listed_date、price、cost、cost_source、stock、manual_stage | 商品表；导入按 sku 覆盖，但 cost、manual_stage 那一格为空时保留库里原值；cost_source 记成本来自导入还是页面补录；manual_stage 为店主标记的生命周期 |
| sales_day | sku + day | price、units、amount、refunds、visitors、ad_spend、ad_units | 销售日记录；导入按 sku + day 覆盖；后四列可空 |
| competitor | sku + idx | price、day | 竞品价格，idx 为 1 到 5 |
| setting | key | value（JSON） | 店铺参数覆盖值、店铺名、是否已确认设置 |
| setting_log | id | at、field、old、new | 设置变更日志 |
| category_elasticity | category | base、adjust | 类目基准弹性与微调，生效值 = base ×（1 + adjust） |
| column_mapping | tbl + signature | mapping（JSON） | 记住的列名映射，signature 为排序后的原始表头 |
| pending_upload | token | payload | 等待确认列名的上传文件，一天后清理 |
| import_log | id | at、status、files、detail | 每次导入的结果：成功或拒收、覆盖行数、错误清单 |
| calc_run | id | at、reason、as_of、extra（JSON） | 每次重算一版；as_of 为全店销售记录最后一天；extra 存本版改价事件与类目校准 |
| sku_result | run_id + sku | status、data（JSON）、fp、note | 每版每个 SKU 的基础量与建议。fp 是输入指纹（参数、商品、销售、竞品、单品覆盖、类目校准、今天）；指纹没变就沿用上一版状态（已查看 / 已采纳 / 已忽略），旧行记「已沿用」；变了旧行记「已过期」、新行「新建」 |
| sku_override | sku | data（JSON） | 单品输入面板的覆盖：扣点率、履约费、退货率与损耗、最低毛利率、目标清仓天数、弹性微调；与店铺默认相同的不存 |
| adoption | id | sku、run_id、at、as_of、price、current_price、low、opt、high、out_of_range | 采纳记录；低于最低建议价不收；高于最高建议价记区间外；输入变化后记录仍在 |
| ignore_log | id | sku、run_id、at、reason、direction | 忽略记录；原因三选一；7 天内同向（涨价 / 降价 / 维持）的新建议直接记「已忽略」 |
| view_log | id | sku、run_id、at | 打开单品页的记录，采纳率的分母 |

## 3 参数文件

config/params.default.json 保存 PRD 9.1 的全部默认值，代码里不硬编码数值。设置页的改动写进 setting 表，生效参数 = 默认值被设置覆盖。

| 分组 | 键 |
|-|-|
| 店主填（默认值取验收样例店，只是占位） | 平台、平台默认扣点率、扣点率、单件履约费、退货率、单次退货净损失占比 |
| 店主可改 | 最低毛利率、尾货期最低毛利率、目标清仓天数、滞销线 |
| 口径 | 单件广告成本口径、近期天数、数据不足记录天数、新品期上架天数、新品期累计成交、尾货期日均比、贴近成本系数、疑似偏高 / 偏低线、改价事件窗口天数、改价事件最小幅度（1%）、活动日倍数 |
| 模型 | 类目先验、全类目先验、弹性微调上限、弹性硬限、曝光倍数、候选价上限倍数、候选价步长、区间宽度、预计可增毛利天数（14）、竞品裁剪、置信度、忽略冷却天数 |

平台默认扣点率四个平台先都占位 5%，标【假设】，门 0 后按目标店后台实际扣点改。

## 4 计算模块接口

全部在 advisor/calc.py，输入普通数据，输出字典，不读写数据库。

| 函数 | 输入 | 输出 |
|-|-|-|
| breakeven | 成本价、参数、单件广告成本 | 保本价，四舍五入到分 |
| unit_ad_cost | 某 SKU 的日记录、近 30 天日期 | 单件广告成本、广告花费、广告成交件数、口径说明 |
| activity_days | 日记录、参数 | 活动日集合 |
| price_events | 日记录、参数 | 改价事件日期列表 |
| lifecycle | 商品、上架天数、累计成交、库存天数、两段日均、参数 | 生命周期与来源（店主标记 / 自动） |
| base_quantities | 商品、日记录、今天、参数 | 单个 SKU 全部基础量，字段同计算明细导出 |
| compute_all | 全部商品、全部日记录、参数 | 今天与全部 SKU 的基础量 |
| event_elasticity、calibrate | 日记录、改价日、活动日、参数；全店事件 | 单个事件的转化或销量弹性；按类目的有效事件数、中位数、校准误差 |
| model.resolve_elasticity | 类目、校准结果、设置里的基准与微调、参数 | 生效弹性与来源：类目事件 ≥ 3 个用本店校准，否则用基准，再叠加微调，夹在硬限内 |
| model.suggest | 单个 SKU 基础量、生效弹性、竞品价、参数 | 区间三点、健康度、置信度、预估、解释四句、预计可增毛利、候选上下限 |
| model.Estimator、estimate_rows | 基础量、弹性、参数；任意价格 | 该价的日销量、日毛利、日成交额、转化率、库存清完天数，及与当前价的六行对比 |

口径与数据体检脚本（仓库里的 gate0/）一致。规格没写死、开发时补定的口径（C-01 到 C-12）见第 8 节。候选价下限用未取整的保本价 ×（1 + 最低毛利率）向上取到分，保证建议价单件毛利不为负。

## 5 页面路由

| 路径 | 方法 | 用途 |
|-|-|-|
| / | GET | 健康度列表：统计卡、五档筛选胶囊（?f=）、排序（?sort=gain / stock / margin）、每 SKU 一行；进单品页带 back 参数，返回保留筛选与排序 |
| /sku/{sku} | GET | 单品建议（三栏对照图 P4）：价格卡、滑块、预估对比、日毛利曲线、解释四句、输入面板、底部采纳栏；打开即把「新建」记为「已查看」 |
| /sku/{sku}/inputs | POST | 保存或恢复单品输入，只让这个 SKU 的建议过期 |
| /sku/{sku}/adopt | POST | 采纳；低于最低建议价拒收，高于最高建议价记区间外，弹层提示去平台后台改价 |
| /sku/{sku}/ignore | POST | 忽略，原因必选 |
| /sku/{sku}/estimate?price= | GET | 任意价的预估（滑块用），只在本机请求 |
| /import | GET、POST | 导入页与上传；拒收时显示错误清单 |
| /import/mapping | POST | 确认列名映射后导入，确认过的映射记住 |
| /import/issues/{id}.csv | GET | 下载错误清单 |
| /templates/{表名}.csv | GET | 下载三张模板 |
| /report | GET | 体检报告：指标表（MRD 2.2 与附录 A.4）、健康度与库存天数分布、弹性校准与改价事件 |
| /settings | GET、POST | 店铺参数与类目弹性；保存即全店重算 |
| /settings/log | GET | 设置变更日志 |
| /export/detail.csv | GET | 导出计算明细（含建议区间、健康度、置信度、弹性、解释） |
| /export/events.csv | GET | 导出改价事件与弹性 |
| /export/simulation.csv | GET | 导出模拟推演，每行标「模拟」，不进任何页面指标 |
| /export/adoptions.csv | GET | 导出采纳记录：SKU、采纳价、采纳时间、是否区间外等 |
| /export/gate1.csv | GET | 门 1 评估：采纳率，每个采纳 SKU 的对照、前后 14 天毛利率、差值 |
| /sku/{sku}/cost | POST | 补录成本价 |
| /sku/{sku}/stage | POST | 手动标记生命周期，留空 = 自动 |
| /healthz | GET | 启动检查 |

## 6 测试策略

| 层 | 做法 |
|-|-|
| 计算层 | pytest 单元测试：舍入、活动日、改价事件（含 1% 最小幅度）、广告口径、手动标记优先、候选价下限不亏钱 |
| 反例集 | samples/反例集 由门 0 脚本从样例店抽出六类；tests/test_counter.py 逐类断言 PRD 12.4 的正确表现 |
| 验收样例集 | scripts/make_samples.py 按验收条例附录 A 生成 12 个虚构 SKU、答案表与全部变体（坏文件、列名不同、无广告列、S09 活动日、150 个 SKU × 90 天规模样例） |
| 自检命令 | scripts/accept.py PT-xx：每条输出条目、通过、实测；每个场景用临时空库，不碰正式库 |
| 回归 | pytest 把 PT-02 到 PT-12 的自检当回归测试跑，机器可判条目不许有不通过；导入空格保留原值有单独测试 |
| 冒烟 | scripts/smoke.py：空库 → 导入样例店 → 确认参数 → 体检 → 列表 → 单品 → 采纳一条 → 导出采纳记录 |
| 页面 | 每步交付前在浏览器里走一遍导入、设置、总览 |

## 7 启动方式

| 做什么 | 命令 |
|-|-|
| 装环境 | uv sync |
| 启动工作台 | uv run advisor，自动打开 http://127.0.0.1:8321 |
| 换库或端口 | uv run advisor --db 文件路径 --port 端口 --no-browser |
| 双击启动 | scripts/启动定价参谋.command |
| 备份与恢复 | uv run advisor-backup；uv run advisor-restore 备份文件 |
| 冒烟 | uv run python scripts/smoke.py |
| 自检 | uv run python scripts/accept.py（不带参数 = PT-01 到 PT-12） |
| 测试 | uv run pytest -q |

数据在 data/advisor.db，不进提交；备份在 data/backups/，文件名带日期。静态文件地址带修改时间做版本号，升级后浏览器不会用旧缓存。

## 8 口径补充

规格没写死、开发时必须定下来的口径。数据体检脚本与工作台用同一套。

| 编号 | 口径 |
|-|-|
| C-01 | 无动销的商品在体检里单列计数，不进各项占比的分母 |
| C-02 | 体检各项占比的分母 = 非数据不足的商品数 |
| C-03 | 活动日：此前 30 天有记录的日子少于 7 天、或中位数为 0 时不判，避免慢动销商品卖出 1 件就算活动日 |
| C-04 | 改价事件：当日售价与前 7 天每一天的差都 ≥ 1%，一次调价只记一个事件；几分钱的日常波动不算 |
| C-05 | 校准误差 = 类目内事件弹性对中位数的中位绝对偏差 ÷ 中位数的绝对值 |
| C-06 | 对照基线：同类目库存天数最接近的商品作对照，每 7 天切一刀比前后 14 天毛利率变化之差，取 P10 到 P90；窗口剔除活动日，有效天数少于 10 天不算 |
| C-07 | 模拟推演的建议价取当前这一版的最优价，不按日重算；模拟销量 = 真实销量 ×（建议价 ÷ 真实价）的弹性次方 |
| C-08 | 导入时商品表的成本价或生命周期标记那一格为空，保留库里原值（页面补录的成本、手动标记），导入结果逐条说明「沿用」 |
| C-09 | 候选价下限 = 未取整的保本价 ×（1 + 最低毛利率）向上取到分；金额相乘用十进制算 |
| C-10 | 「输入变化」按商品的输入指纹判：店铺参数、商品、销售、竞品、单品覆盖、类目校准、数据截至日任一变化，这个商品的旧建议才过期；没变的沿用已查看、已采纳、已忽略状态 |
| C-11 | 忽略后 7 天按自然日算，从点「忽略」起；同向 = 最优价相对当前价的方向（涨价、降价、维持） |
| C-12 | 试用评估：采纳率 = 采纳过的商品 ÷ 打开过单品页的商品；锚定日 = 采纳时那一版数据的最后一天，前后各取 14 天；窗口剔除活动日，有效天数少于 10 天记「记录不足」 |
