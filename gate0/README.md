# 数据体检脚本

在正式使用[工作台](../app/)之前，先拿一家店的真实数据跑一遍体检，回答两个问题：需要动价的商品多不多、库存压得重不重。同时产出后面要用的弹性校准值和反例。这是一次性脚本，不属于工作台。

## 用法

需要 [uv](https://docs.astral.sh/uv/)。

```bash
uv sync
uv run python samples/make_samples.py                             # 生成样例店（12 个虚构商品，60 天）
uv run gate0 samples/样例店 --out out/样例店                         # 跑体检
uv run python scripts/accept.py PT-00 samples/样例店 out/样例店      # 自检：从原始 CSV 独立复算，再和体检 Excel 比对
uv run pytest -q
```

真实数据放在 `data/` 下的任意目录（已在 .gitignore 里，不会进提交）：

| 文件 | 说明 |
|-|-|
| 商品表.csv、销售日记录.csv、竞品价格.csv | 列同工作台的导入模板，空模板在 `templates/`；竞品价格可以不给 |
| 店铺参数.json | 扣点率、履约费、退货率与损耗等，模板在 `templates/` |
| 列名映射.json | 后台导出的列名与模板不同时写，模板在 `templates/` |

CSV 支持 UTF-8 与 GBK；日期支持「年-月-日」「年/月/日」和八位数字三种写法；金额可带 ¥ 与千分位。坏行不会中断，记在 Excel 的「数据覆盖与校验」页。数据要先脱敏：不含店名、买家信息，商品名可用编号代替。

## 输出

`门0体检.xlsx`，九张表：

| 表 | 内容 |
|-|-|
| 体检 | 贴近成本、疑似偏高、疑似偏低、需要动价、库存超 90 天等指标，以及是否达标的判定 |
| 答案表 | 每个商品的保本价、毛利率、日均、库存天数、生命周期、数据不足原因 |
| 改价事件、类目校准 | 每个改价事件算出的弹性；按类目取中位数，事件少于 3 个的类目用经验值 |
| 活动日 | 成交异常高的日子，不参与弹性校准 |
| 反例集 | 六类容易算错的情形各挑一个商品，写明正确表现 |
| 对照基线 | 不改价时，同类商品之间毛利率变化的自然波动区间 |
| 数据覆盖与校验、参数与口径 | 行数、坏行、用到的参数与算法 |

另有 `答案表.csv` 和 `反例集/`（三张表加说明），工作台的自动测试会用到。

## 判定

需要动价的商品占比 ≥ 30%，且库存超 90 天的商品占比 ≥ 15%，才算问题成立。占比的分母是非数据不足的商品；无动销的商品单列，不进分母。口径细节见[技术方案](../app/docs/技术方案.md)第 8 节。
