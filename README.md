# 定价参谋 price-advisor

给中小电商店主的定价辅助工具：改价前算清毛利，只给建议，不代改价。

## 解决什么问题

多 SKU 的小店店主每周都要决定三件事：哪几个商品该动价、动到多少、动了大概会怎样。手上常见的依据有三种：平台的建议价（只往下，不含店主自己的成本）、同行价格（靠逛）、进货价乘倍率（不考虑销量变化）。没有一步回答「改完还剩多少毛利」。

定价参谋站在店主毛利这一侧：用店主自己导出的商品、成本和销售记录，给每个商品一个含保本线的建议价区间，并说明为什么。

## 它做什么

一条流程，四个页面：

| 步骤 | 做什么 |
|-|-|
| 导入 | 上传三张 CSV：商品表、销售日记录、竞品价格（可选）。逐行校验，任何一行出错整批不导；列名和模板不一样时确认一次对应关系 |
| 体检报告 | 全店一张表：贴近成本、疑似偏高、疑似偏低、库存超 90 天的商品各占多少，健康度与库存天数分布，弹性校准 |
| 健康度列表 | 每个商品一行：保本价、健康度、建议区间、置信度、预计可增毛利。贴近成本的排最前 |
| 单品建议 | 区间三点、保本线、四句解释、预估对比、日毛利曲线、任意价试算；店主点「采纳」或「忽略」，工具只记录 |

## 怎么算的

- **保本价** =（成本价 + 单件履约费 + 单件广告成本）÷（1 − 平台扣点率 − 退货率 × 单次退货净损失占比）。任何建议价都不低于保本价 ×（1 + 最低毛利率）。
- **生命周期**决定目标：新品期看销量，成熟期看日毛利，尾货期要在目标天数内清完库存。店主可以手动标记。
- **价格弹性**：本店某个类目的改价事件够多（3 个及以上）时用本店数据校准，否则用类目经验值，并在解释里说明。
- **建议区间**：在候选价里找目标值最大的价作为最优价，目标值不低于最优 90% 的两端作为最低与最高。录了 2 个以上竞品价时按竞品中位价裁剪范围。
- **置信度**：高、中、低三档。记录不够时照样给区间，但弱化显示并提示「先小幅试」。
- **解释**固定四句：结论、原因、预估、边界。估不出的项写「未计」，不编数字。

## 快速开始

需要 [uv](https://docs.astral.sh/uv/)。

```bash
cd app
uv sync
uv run advisor
```

浏览器会打开 `http://127.0.0.1:8321`。在「导入」页上传 `app/samples/样例店/` 里的三张表，就能看到全部页面。样例店的商品和数字都是虚构的。

## 边界

- 不自动改价：工具没有任何写平台价格的能力，改价由店主自己到平台后台做。
- 不抓取竞品：竞品价由店主手动录入。
- 不做按买家分流的价格实验。
- 不跨店汇总：一个数据库只放一家店的数据。
- 数据只存本机的 SQLite 文件，运行时不发任何外部请求。

## 已知限制

- 销量随价格的变化按常弹性估算，弹性默认用类目经验值。毛利率较低的成熟期商品，最优价容易顶到候选上限（当前价 × 1.3）。预估只用来解释建议，不是承诺。
- 价格变化带来的曝光（流量）变化没有计入，所以置信度最高只到「中」。
- 忽略过的建议目前只改状态，列表顶部的统计仍把它算在内。
- 只支持单店、单用户、桌面浏览器，最小宽度 1280。
